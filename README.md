# 塔防 + 弹药合成（Tower Defense Alchemy）— 可玩原型

一个验证"塔防 + 弹药合成"核心玩法的 HTML5 原型，面向 iPad Safari 全屏触控体验。
技术栈：**Phaser 3 + TypeScript + Vite**，纯逻辑层用 **vitest** 做单元测试，
并附带一个 **headless 平衡性模拟脚本**，用简单 AI 自动跑几十局游戏来检查数值是否合理。

> 当前阶段美术资源全部是程序化生成的几何图形（圆形/方形/描边色块），
> 目的是先验证系统深度和节奏是否好玩，暂不投入美术制作。

## ✅ 已实现的功能

### 塔防基础循环
- 固定折线路径地图，敌人从起点走到终点，漏怪扣血，血量归零游戏结束。
- 2 种炮塔：**近程速射塔**（单体、攻速快）、**范围溅射塔**（AOE、攻速慢）。
- 3 种敌人：**普通兵**、**快速兵**（速度快血少）、**坦克兵**（护甲高、血厚，精英/稀有掉落来源）。
- 击杀掉落金币，护甲按百分比减伤。

### 波次与节奏（备战 / 战斗分离）
- 5 波构成一关，每波结束进入"备战阶段"：无强制倒计时，UI 显示"建议备战 30s（可随时开始）"作为柔性提示，
  玩家可随时点击"开始下一波"提前进入战斗。
- 战斗阶段熔炉合成入口自动锁定（按钮置灰且点击被拦截，而不只是视觉上变灰），
  玩家只能拖拽弹药架里已合成好的弹药到炮塔，或者调整已部署的炮塔。
- 通关后有结算面板（波次数、金币、合成次数、大成功/大失败次数等统计）。

### 弹药合成系统（核心玩法）
- **固定配方 + 区间随机**：素材类型标签组合决定配方（比如"火系×2 → 火种弹"），
  但具体数值（伤害、暴击率、附加效果强度）在该配方的区间内随机浮动，
  避免纯随机导致玩家无法建立策略记忆。
- **配方图鉴（Recipe Journal）**：已发现的配方会被记录，可在熔炉界面查阅。
- **合成预测**：选择素材后，合成前展示伤害区间、暴击率区间、"大成功/大失败"概率的可视化风险条；
  确认合成后有开箱式动画（数值从模糊态"揭晓"为最终值）。
- **临时 / 永久弹药双轨制**：临时弹药消耗更少素材，装填到塔上后有使用次数/时间上限（倒计时从装填那一刻开始，
  躺在弹药架里不消耗时效）；永久弹药消耗更多稀有素材+金钱，且数值有明确折扣（如伤害 -20%），
  两者的数值权衡在合成界面直接标注。
- **弹药架**：6-8 格上限（制造资源稀缺感），横向卡片展示颜色/图标/关键属性，可从战斗阶段拖拽装填到炮塔。
- **炮塔弹药槽可视化**：装填后炮塔颜色/发光随弹药类型变化，并显示剩余时效的倒计时圆环。
- **弹药耗尽自动回退默认弹药**：临时弹药到期/用尽次数后，炮塔不会完全哑火，而是自动回退到塔身自带的
  基础属性（伤害较低但保底可用）继续攻击，只是输出效率下降而不是防线破功；回退瞬间会有一次
  红色冲击波+浮动提示文字（"弹药耗尽!已切换默认弹药"），并在塔身角标上留下一个灰色描边标记
  （与"从未装填过弹药"的裸塔区分开），提醒玩家这里已经掉级、值得重新装填。
- **弹药状态可视化警示系统**：每个已装填临时弹药的塔头顶有一个倒计时圆环，剩余量（时间/次数取较紧迫者）
  用颜色分级——绿色(充足) → 黄色(≤30%,告警) → 红色+闪烁(≤10%,危急)；HUD 上会出现
  "⚠ 弹药偏低/即将耗尽 xN（点击定位）"提示，点击后会在所有告急塔位原地播放一次脉冲高亮
  （当前地图为单屏可见，故用原地高亮代替摄像机滚动定位），方便同时管理多座塔时快速找到需要补弹的塔。

### 素材获取
- **主要**：波次结算/关卡间的商店界面，用金币购买素材（列出类型标签与效果说明）。
- **次要**：击杀敌人有概率直接掉落素材（免费拾取）。
- **稀有**：精英/坦克类敌人有低概率掉落稀有素材，合成出的弹药有更强效果或独特视觉（如粒子色彩）。

### 项目结构
```
src/
  core/            纯逻辑层（不依赖 Phaser，可单元测试）
    craftingEngine.ts  合成引擎：配方匹配 + 属性计算 + 区间随机
    economy.ts         金币/素材钱包
    ammo.ts             弹药实例（时效计算、临时/永久）
    combat.ts           塔的索敌/开火/伤害结算
    gameSession.ts       游戏会话状态机（波次/阶段/胜负判定），复用于渲染层与 headless 模拟
  config/          数值配置（素材/配方/敌人/塔/波次/地图），纯 TS 常量，方便调参
  scenes/          Phaser 场景（渲染 + 输入交互）
tests/             vitest 单元测试（覆盖合成引擎/经济/弹药/战斗/会话）
scripts/
  headlessSim.ts   headless 平衡性模拟：用简单 AI 自动跑 N 局，输出胜率/存活/合成等统计报告
  smoke3.mjs       Playwright 端到端冒烟测试（建塔→商店→合成→拖拽装填→开战），手动运行用于回归验证
```

## 🧩 设计理念：炮塔与弹药系统分工（核心设计原则）

> 这条准则同时写在 `src/config/towers.ts` 顶部注释里，方便后续新增塔类型时对照。当前 MVP 的两种塔已大致遵循此原则，暂不需要为此重构，但后续扩展塔类型/弹药特效时应以此为准。

**核心原则：塔决定"机制骨架"（怎么打），弹药决定"内容强度"（打出什么效果），两者是相乘关系，不能重叠。**

- **炮塔（Tower）负责**：攻击的物理形式（单体高频 / 范围溅射 / 连锁跳跃 / 持续光束等）、基础攻速/射程/造价、
  弹药槽数量与倍率加成、花钱购买和升级（升级应强化数值和槽位，**不应该**决定伤害类型或元素属性——那是弹药该管的）。
- **弹药（Ammo）负责**：伤害的元素属性（火/冰/毒/物理）、附加特效（灼烧 DOT / 减速 / 连锁感染等）、
  具体数值区间（伤害/暴击率）。

**关键设计技巧**：同一种弹药装在不同塔上，因为塔的机制不同，实际效果应该不同——比如"燃烧弹药"装在单体塔上是
"命中目标持续燃烧"，装在溅射塔上是"命中点范围内持续燃烧"。这样让塔和弹药形成"相乘"而非简单相加的策略深度，
逼玩家思考稀有弹药该分配给哪个塔才能最大化价值。

**建议的塔类型分工方向（供后续扩展参考，不需要在当前 MVP 全部实现）**：
- 速射塔：攻速快单体，2 槽，适合装限时消耗型弹药（弹药消耗快，正好匹配"临时弹药"机制）。
- 重炮塔：攻速慢单发伤害大，1 槽但加成倍率高，适合装稀有/永久弹药，一发入魂。
- 溅射塔：范围伤害，弹药的 AOE/DOT 特效在这里价值最大化。
- 连锁塔：命中跳跃到附近敌人，适合装减速/感染类特效弹药。

塔的地形/位置策略（拐角覆盖、路径规划等传统塔防乐趣）应完整保留，不要被弹药系统覆盖掉，这是塔防玩家的基本预期。

## 🧪 测试与自测方式

```bash
npm install
npx vitest run              # 44 个单元测试：合成引擎/经济/弹药时效/战斗/会话状态机
npx tsc --noEmit             # 类型检查
npx tsx scripts/headlessSim.ts 100   # 跑 100 局 headless 模拟，输出平衡性报告
node scripts/smoke3.mjs      # 端到端 UI 冒烟测试（需要先 npm run dev 或使用其内置的临时 server）
```

### Headless 模拟结论（用于数值调参依据）
用一个"合理但不追求最优"的自动策略（有空格就建塔、随机买 1-2 种素材凑对合成临时弹药、
弹药架有货就装填到未装填的塔、备战阶段结束立即开战、战斗中随时补装弹药架里剩余的弹药）
跑 100 局第一关的结果：

- 胜率约 **43%-50%**（初始金币从 120 调到 150 后，从 ~22% 提升到此区间）
- 平均完成波次 ≈ 4/5，平均剩余生命 ≈ 4-5/20
- 说明关卡对"被动/朴素"打法有相当的失败率，但并非不可通关；
  真人玩家通过更好的塔位选择、更针对性的配方搭配、及时补装弹药，预期胜率会明显更高——
  符合塔防"有策略深度、有一定失败率"的目标体验，而非无脑必胜或必败。

## 🖥️ iPad / 触控适配要点

- `viewport-fit=cover` + `user-scalable=no`，Canvas 全屏铺满，避免浏览器手势与游戏拖拽冲突。
- Phaser 场景内的拖拽（弹药卡片→炮塔）同时支持鼠标与触摸指针事件。
- 建议横屏使用（当前地图/HUD 布局针对 1024×768 横向画布设计）。

## ⚠️ 已知问题 / 后续优化方向

1. **Phaser Container 输入限制的绕过方案**：开发中发现 Phaser 3 的输入命中排序
   （`InputPlugin.sortGameObjects`）依赖 `camera.renderList.indexOf`，而 **Container 的子对象不会被单独加入
   renderList**，导致嵌套在 Container 里的可交互对象在与顶层对象（如模态遮罩）重叠时永远排序垫底、点击优先级最低，
   与 `.depth` 值无关。当前的解决方案是把所有真正需要点击的按钮/热区做成**顶层（非嵌套）**的
   Rectangle/Circle + 一个手写的 `absolutePos()` 父链坐标累加辅助函数，仅用纯装饰性的 Container 做视觉分组。
   这个方案work，但增加了一些样板代码；如果未来 UI 复杂度继续上升，值得评估换成 DOM overlay 或专门的 UI 插件。
2. **包体积**：生产构建 JS 约 1.23MB（gzip ~330KB），主要是 Phaser 本身。当前阶段可接受，
   后续如果加入更多素材/贴图，值得考虑动态 import 分包。
3. **数值平衡是初步的**：目前只跑了一种"朴素自动策略"的 headless 模拟，尚未针对"更优策略"或
   "更差策略"做对照实验，也没有做多关卡的长期数值曲线规划（当前只有 1 关 5 波）。后续应该：
   - 增加第 2-3 关，逐步引入新素材/配方与更强敌人组合；
   - 针对"极端策略"（比如完全不合成永久弹药、只囤永久弹药）做更多 headless 对照跑，避免出现某种"必胜套路"；
   - 收集真人测试反馈后再微调波次强度曲线与素材/配方价格。
4. **合成结果的视觉表现较简单**：目前用颜色/描边区分弹药类型和品质（大成功会有额外描边高亮），
   还没有做真正的粒子特效或"开箱"物理动画，只是数值揭晓的渐变动效。
5. **单元测试只覆盖核心数值逻辑**，但没有针对 Phaser 渲染层写自动化测试（渲染层用 `scripts/smoke3.mjs`
   做手动/半自动回归，尚未接入 CI）。后续可以考虑把 smoke 测试也纳入 CI（需要无头浏览器环境）。
6. **弹药告急高亮目前是"原地脉冲"而非摄像机定位**：当前地图固定单屏可见，所以点击 HUD 告警只做了原地
   高亮效果；如果未来地图变大需要滚动，需要补充真正的摄像机平移/跳转逻辑。

## 🗺️ 后续规划 / Roadmap

### 即时合成"硬核模式"（未实现，规划中）
作为当前"备战合成、战斗锁定"经典模式的补充玩法，计划推出第二种可解锁模式，主打
**"实时生产管理压力 + 手忙脚乱的爽感"**，与主线"策略规划"模式形成互补，定位为中后期解锁内容：

- **战斗中随时合成**：熔炉不再锁定，但代价是节奏更紧张——某些塔/敌人存在"克制关系"
  （比如特定敌人只对"冰系"弹药有额外伤害加成），逼玩家在战斗中临时决策"现在必须马上做一发冰系弹药"。
- **合成从瞬间完成改为"熬制"机制**：配方投入后需要等待 N 秒才能出炉；引入"多熔炉并行生产"
  （花钱解锁更多熔炉位）与"加速/催熟"消耗品/付费选项，制造资源分配的决策张力。
- **"残渣"系统**：合成失败或产生副产物时生成残渣，玩家可以选择：回收（降低下次合成成本但拉低品质上限）、
  贱卖换取少量金币、或攒够数量合成一个"保底弹药"，让失败也有产出而不是纯粹惩罚。
- **传播点设计**：这种"实时抢时间做弹药续命"的高压场面天然适合做成短视频式的高光时刻（例如
  "我如何在10秒内切换配方续命"），可以作为该模式对外传播/引流的素材方向。

## 部署流程说明

`.github/workflows/deploy.yml` 会在每次推送到 `main` 或 `master` 分支时：
1. 安装依赖、跑 `vitest`、跑 `tsc --noEmit`；
2. `npm run build` 生成 `dist/`（`vite.config.ts` 在 CI 环境下自动使用
   `base: '/tower-defense-alchemy/'` 以匹配 GitHub Pages 的子路径）；
3. 上传并发布到 GitHub Pages。

首次启用需要仓库管理员在 GitHub 仓库设置里把 **Pages → Source** 改为 **GitHub Actions**（只需设置一次）。
